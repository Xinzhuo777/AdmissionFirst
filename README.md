# AdmissionFirst experiment artifact

This candidate artifact contains the experiment implementation and selected
observations for the unified 5–6 November 2026 AdmissionFirst campaign. It
includes a frozen ordinary-baseline source tree alongside the final experiment
implementation. The release copy adapts machine paths, native-build checks and
selected descriptive metadata; the experimental case definitions and decision
conditions are preserved.

**Validation status:** the complete 11-stage campaign has not yet been run
end to end from this package. On macOS arm64 with Python 3.9 and PostgreSQL 16,
the native extension, admission checks, E1, E2, E4, E5 and E7 have been exercised. The
E10 analysis was rerun against the original raw measurements and reproduced
the original case and family results. These checks are not a guarantee that
all other stages or environments work. An older selection-cost CLI also needs
a reference document that is not included and is outside the checked path.

## Contents

- `code/`: experiment code, workload definitions, configurations, baseline,
  campaign and analysis drivers.
- `results/`: selected measurements and statistical summaries from the
  original run, plus a script to check the main workload medians. See
  [results/README.md](results/README.md) for included fields and limitations.

Raw input data, all raw experimental logs and the manuscript are not included.
The selected results support partial statistical checks; they do not contain
every record needed to reproduce all confidence intervals or correctness
checks without running the experiments.

## Environment and external data

The checked environment used macOS arm64, Python 3.9.10, PyYAML 6.0.2, a C
compiler and PostgreSQL 16.11 (`initdb`, `pg_ctl`, and `psql` on `PATH`).
A full run requires substantial time, memory and free disk space. The campaign
uses PostgreSQL `shared_buffers=2GB`, `work_mem=16MB` and
`effective_cache_size=8GB`. Results and performance depend on the machine.

The mixed workload requires TPC-H SF1 and the JOB 2013 IMDb snapshot; the SF10
workload requires TPC-H SF10. Obtain the
[TPC-H 3.0.1 tools](https://www.tpc.org/tpc_documents_current_versions/download_programs/tools-download-request5.asp?bm_type=TPC-H&bm_vers=3.0.1&mode=CURRENT-ONLY)
under their terms, generate the four required tables, and consult the
[CWI JOB snapshot notice](https://event.cwi.nl/da/job/readme.txt) before using
its data. Place the files under `code/datasets/`:

```text
tpch/sf1/{customer,orders,lineitem,nation}.tbl
tpch/sf10/{customer,orders,lineitem,nation}.tbl
imdb/csv/{title,movie_companies,cast_info,kind_type,company_type}.csv
```

These lines describe individual files, not literal brace-containing filenames.
The application workload uses a synthetic dataset generated by the code.
Third-party datasets and generator binaries are not distributed here. See
[DATASETS.md](DATASETS.md) for preparation commands.

## Build and run

The following is the candidate full-campaign entry point; only the individual
checks listed above have been verified so far.

```sh
cd code
python3.9 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
python -m caprls_core.build_identity_primitives
python -B study/run_campaign.py
python -B study/run_analysis.py
```

The native extension is built locally and verified at runtime. PostgreSQL temporary
clusters use the system temporary directory by default. Set `CAPRLS_TMPDIR` to
a short, writable directory if needed: macOS limits Unix socket path length.
The campaign
creates a fresh `results/raw/a018-unified` directory and refuses to overwrite an
existing run. The analysis requires all eleven stages to finish and creates a
fresh `results/analysis/a018-unified` directory. On failure, preserve and inspect
the output before choosing a fresh location or removing a failed run.

To verify the included main-workload medians without a database, run from the
repository root:

```sh
python3 results/verify_results.py
```
