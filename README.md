# AdmissionFirst

AdmissionFirst is a planner for queries with row-level access control. This
repository contains the PostgreSQL experiment code and results for
AdmissionFirst and its baselines.

## Check the results

The `results/` directory contains measurements and summaries from the
experiments. To check the reported execution-time medians, run this from the
repository root:

```sh
python3 results/verify_results.py
```

See [results/README.md](results/README.md) for what is included.

## Run the experiments

You will need Python 3.9, a C compiler, PostgreSQL 16 (`initdb`, `pg_ctl`, and
`psql` on your `PATH`), and at least 50 GB of free disk space. The checked
setup used macOS arm64, Python 3.9.10, and PostgreSQL 16.11. The experiments
use a PostgreSQL configuration with 2 GB of shared buffers.

First, prepare TPC-H SF1 and SF10 and the JOB/IMDb dataset as described in
[DATASETS.md](DATASETS.md). The application dataset is generated by the code.

Then install the package and run the experiments:

```sh
cd code
python3.9 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
python -m caprls_core.build_identity_primitives
python -B study/run_campaign.py
python -B study/run_analysis.py
```

The campaign writes to `code/results/raw/experiments/`; the analysis writes
to `code/results/analysis/experiments/`. Both require a fresh output
directory. The analysis starts after all 11 stages finish. On macOS, set
`CAPRLS_TMPDIR` to a short, writable path such as `/tmp` if PostgreSQL reports
that its socket path is too long.

## What has been checked

Stages E1, E2, E4, E5, and E7 have been tested individually. We have also
checked the admission cases, content specification, and E10 analysis. The full
11-stage campaign has not yet been tested end to end.
An older selection-cost CLI also requires a reference document that is not
included.

The included results contain selected measurements, not the full raw logs;
they are enough to check the main execution-time medians but not every
confidence interval or correctness check. Input datasets are obtained
separately.

## Repository layout

- `code/` — planner, baselines, workloads, and experiment scripts
- `results/` — selected measurements, summaries, and a verification script
- [DATASETS.md](DATASETS.md) — dataset download and preparation steps
